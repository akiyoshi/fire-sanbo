### Eng Dual Voices 主要発見

#### CLAUDE 主モデル (eng)

(私の独立分析と Architect サブエージェント結果は強く一致した。重複避けて Outside Voice に統合)

#### OUTSIDE VOICE (eng — architecture チャレンジ — `[single-model: architect agent]`)

**🔴 CRITICAL #1: residentTax 二重計上（実装前に修正必須）**

`simulation/engine.ts:65-68` は在職中の各年に `calcAnnualTax(salary, age)` を呼び、その年の `residentTax` を **同年** taxBd に計上している（発生年課税モデル）。§5.3 の素直な実装をそのまま入れると:

- 退職前年 (`retirementAge - 1`) の住民税が **当年に1回計上**
- かつ §5.3 の `residentTaxLag = prevYearTax.residentTax` で **退職翌年 (`retirementAge + 1`) にもう1回計上** ← 二重

**正しい修正案:** §5.3 を変更し、**退職年の `residentTax` 計上を退職翌年に繰り延べる** （在職モデルは「翌年課税」に統一）。または最小修正として、退職前年 (`retirementAge - 1`) の `residentTax` を退職年 ではなく退職翌年に計上するパッチ。テスト必須。

**🔴 CRITICAL #2: FormState v5→v6 マイグレーション（実装前に修正必須）**

`form/storage.ts:25`:
```ts
if (data.version === FORM_SCHEMA_VERSION) return data.form;
```
は厳密一致のみ受理。v6 にバンプした瞬間、**全ユーザーの localStorage（保存シナリオ含む）が消滅**する。`importFormFromJSON` の URL 復元も同様。

**修正案:** `migrateV5toV6(legacy: FormStateV5): FormStateV6` 追加し、`if (data.version < FORM_SCHEMA_VERSION) return migrate(data)` パスを実装。`idecoConfig` `retirementBonus.receiveAge` を Optional + デフォルト null/undefined で吸収。共有URL も同経路。

**🟠 HIGH: idecoTiming 軸の交互作用問題**

`prescription/engine.ts` の既存4軸は独立な二分探索（O(n) 各軸）。`idecoTiming` は離散16点（60-75歳）かつ **退職金手取りに影響 → 退職後初期資産変動 → 既存4軸の探索結果が変わる**。単純に5軸目として追加すると:
- 「支出 −5%」と「iDeCo を 70歳に」の合成は加法的にならない
- ユーザーが両方適用すると期待外の結果

**修正案:** idecoTiming は外側ループで離散探索 → 内側で4軸独立探索 → 最良組合せ選択の **二層構造**。計算量 ~16× 増、Worker 内で 1-2秒。UI にプログレスバー必須。

**🟠 HIGH: SWR ロジックを `swr/engine.ts` で再実装すると DRY 違反**

`prescription/engine.ts:362-378` の expense 軸二分探索と SWR は同じ計算。学習記録「runTrialLite 同期問題」の再来になる。

**修正案:** `swr/engine.ts` は薄いファサード。内部で `prescription` の二分探索ヘルパー（要 export）を呼ぶ委譲パターン。

**🟡 MEDIUM: gap=0 ガード**

`calcEffectiveYearsForLumpSum` で `secondaryYears - overlap` が負になり得る → `Math.max(0, ...)` 必須。

**🟡 MEDIUM: marginalRate プラミング**

`calcAnnualTax` は税額のみ返却 → `calcFurusatoLimit` 呼出時に再計算が必要で DRY 違反。`calcAnnualTax` の戻り値に `marginalIncomeTaxRate` を追加。
